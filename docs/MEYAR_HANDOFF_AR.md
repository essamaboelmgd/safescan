# Meyar | معيار — شرح وتشغيل المشروع

## المساهمة ونسبة العمل

هذه النسخة تحديث للواجهة والهوية والأيقونة والتوثيق لمشروع SafeScan الأصلي. أكمل الأسماء قبل العرض أو التسليم:

- صاحب المشروع والنسخة الأصلية: **[اكتب اسم صاحبك]**
- تحديث الواجهة والهوية والتوثيق: **[اكتب اسمك]**
- مساهمون آخرون: **[اكتب الأسماء أو احذف هذا السطر]**

Meyar ليس إعادة كتابة مستقلة للنظام؛ واجهة Flutter تستعمل خدمة FastAPI وخوارزميات المشروع الأصلي.

## فكرة البرنامج

Meyar نموذج بحثي يجمع نوعين من الأدلة لمساعدة المستخدم على فحص منتج:

1. يلتقط المستخدم صورة للمنتج أو يختار صورة من المعرض. يحوّل الخادم الصورة إلى خصائص لونية وحواف، ثم يبحث عن صور مرجعية قريبة.
2. يمكن للمستخدم مسح باركود أو إدخاله يدويًا لجلب سجل المنتج ومصدر بياناته.
3. تعرض الواجهة المرشح البصري، بيانات الباركود، المصادر والتحذيرات، وتحفظ سجل الفحص على الخادم.

الصورة المتشابهة أو الباركود لا يثبتان هوية المنتج أو أصالته أو أمانه. تبقى نتيجة **Unknown / Insufficient Evidence** طبيعية عند غياب الدليل أو تعارضه. لا يتصل التطبيق افتراضيًا بخدمة خارجية للكتالوج.

## مكوّنات النظام

- **Flutter / Dart:** التطبيق، الكاميرا والمعرض، ماسح الباركود، عرض الأدلة وسجل الفحوصات.
- **FastAPI / Python:** واجهة الخادم، التحقق من الملفات والطلبات، وتنسيق عمليات البحث.
- **OpenCV وNumPy:** استخراج تمثيل بصري من 192 قيمة مبنية على توزيع اللون HSV وخلايا الحواف، مع بصمة إدراكية للصورة.
- **البحث:** ترتيب مرشحين بالتشابه الكوني الدقيق أو بحث LSH تقريبي يعيد ترتيب المرشحين.
- **SQLite:** حفظ المنتجات والمراجع والصور المرفوعة ولقطات نتائج الفحص.
- **مصنف تجريبي اختياري:** انحدار لوجستي خطي على خصائص مصنوعة يدويًا؛ لا يثبت الأصالة.

التجربة الاستكشافية الموثقة على تسميات ناشر مجموعة الأحذية سجلت **52.05% دقة**، وهي مساوية لخط الأساس الذي يتوقع الفئة الأكثر شيوعًا. هذه النتيجة لا تثبت قدرة على اكتشاف المنتجات المقلدة، ولا تقيس صحة المنتج في الواقع.

## تشغيل نسخة Android على Windows

تحتاج Python وFlutter وAndroid Studio مع Android SDK. افتح PowerShell في مجلد المشروع، ثم نفّذ:

```powershell
Set-Location "C:\path\to\project"
python --version
flutter doctor -v
dart --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
flutter pub get
```

يجب أن يظهر `dart --version` رقمًا **3.13.5 أو أحدث**؛ Flutter يستخدم إصدار Dart المرفق معه.

### 1. تشغيل الخادم

في نافذة PowerShell الأولى:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8000
```

اترك النافذة مفتوحة. افحص الخادم على الكمبيوتر من `http://127.0.0.1:8000/health`. يجب أن تكون قيمة `status` هي `ok`. ظهور `model_available: false` يعني أن الملف التدريبي غير متاح، وليس بالضرورة أن الخادم متوقف. وثائق API في `http://127.0.0.1:8000/docs`.

### 2. تشغيل التطبيق على محاكي Android

في نافذة ثانية:

```powershell
flutter devices
flutter run -d YOUR_EMULATOR_ID --dart-define=API_BASE_URL=http://10.0.2.2:8000
```

`10.0.2.2` هو عنوان الكمبيوتر من داخل محاكي Android القياسي.

### 3. تشغيل التطبيق على هاتف حقيقي

وصّل الهاتف والكمبيوتر بشبكة Wi‑Fi واحدة، ثم شغّل `ipconfig` وخذ عنوان IPv4 لقسم Wi‑Fi. اختبره من متصفح الهاتف بفتح `http://PC_WIFI_IP:8000/health`. بعد تفعيل USB debugging، اعرض الأجهزة ثم شغّل التطبيق مع استبدال العنوان والمعرّف:

```powershell
flutter devices
flutter run -d YOUR_DEVICE_ID --dart-define=API_BASE_URL=http://PC_WIFI_IP:8000
```

اسمح لـ Python على الشبكات الخاصة من Windows Firewall عند الحاجة. لا تستخدم `localhost` على الهاتف؛ فهو يشير للهاتف نفسه. يمكن تعديل عنوان الخادم مؤقتًا من زر الإعدادات داخل التطبيق.

### بناء APK للتجربة

```powershell
flutter build apk --debug --dart-define=API_BASE_URL=http://10.0.2.2:8000
```

ينتج الملف `build\app\outputs\flutter-apk\app-debug.apk`. عنوان المحاكي في الأمر أعلاه؛ استبدله بعنوان الكمبيوتر عند بناء نسخة لهاتف حقيقي. هذا بناء Debug وليس نسخة نشر Release.

## إعادة فحوصات المشروع

بعد تثبيت SDK المناسب والحزم، شغّل من مجلد المشروع:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
flutter analyze
flutter test --reporter expanded
flutter build apk --debug --dart-define=API_BASE_URL=http://10.0.2.2:8000
```

سجل التشغيل الحالي والقيود البيئية موجود في [تقرير التحقق](LOCAL_VERIFICATION.md). لا تذكر نجاح بناء Android أو الاختبارات إلا بعد تشغيلها فعليًا على جهازك.

## خطوات عرض حي قصيرة

1. افتح `/health` وأظهر أن اتصال التطبيق بالخادم يعمل.
2. وضّح مساري الصورة والباركود، وأنهما يجلبان أنواعًا مختلفة من الأدلة.
3. التقط صورة أو اختر صورة، ثم اشرح المرشح البصري ومصدره ودرجة التشابه.
4. اعرض نتيجة `Unknown / Insufficient Evidence` إن ظهرت، واشرح أنها تمنع استنتاجًا غير مدعوم.
5. افتح سجل الفحوصات، ثم اذكر نتيجة التجربة وحدود البيانات والنموذج.

لا تنشئ رسمًا لنتائج غير موجودة، ولا تصف الاختبارات البرمجية على أنها دقة علمية على منتجات حقيقية.
